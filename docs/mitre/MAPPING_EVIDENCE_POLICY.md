# SnareSight MITRE ATT&CK Mapping Evidence Policy

> [!WARNING]
> **CRITICAL OPERATIONAL NOTICE:**
> An ATT&CK mapping indicates that observed behavior is consistent with a documented adversary technique. It does not, by itself, establish attacker identity, successful compromise, intent, or completion of an attack.

---

## 1. Principles of Forensic Evidence Preservation

Every MITRE ATT&CK mapping association generated by SnareSight must be backed by verifiable security telemetry.

1. **Direct Observability:** Mappings must originate from real events recorded by honeypot sensors. Mappings must never be synthesized from assumed, guessed, or fabricated activity.
2. **Privacy & Credential Protection:**
   - Raw plaintext passwords, credential tokens, or private cryptographic keys are **strictly forbidden** from being persisted in mapping evidence.
   - Usernames are represented solely by deterministic one-way SHA-256 fingerprints (`metadata.username_fingerprint`).
3. **Reference-Based Association:** To optimize database storage and maintain evidence provenance, mappings reference existing `security_events` records rather than duplicating large raw payloads.
4. **Historical Immutability:** When mapping definitions or detection policies are updated, previous historical evidence links are never rewritten or deleted.

## 2. Required Evidence by Detection Scenario

| Rule ID | Technique ID | Required Evidence Fields | Corroborating / Optional Fields | Exclusion Conditions |
|---|---|---|---|---|
| `AUTH-001` | `T1110` / `T1110.001` | `event_category == "authentication"`, `outcome == "FAILURE"` | `session_id`, `source_ip`, `metadata.username_fingerprint` | `outcome == "SUCCESS"` |
| `AUTH-002` | `T1078` | `event_category == "authentication"`, `outcome == "SUCCESS"` | `session_id`, `source_ip` | `outcome == "FAILURE"` |
| `AUTH-003` | `T1087` / `T1087.001` | `event_category == "authentication"`, `metadata.username_fingerprint` | `session_id` | Missing username fingerprint |
| `WEB-001` | `T1083` | `event_category == "request"`, `metadata.http_path` | `session_id`, `source_ip` | Missing requested path |
| `WEB-002` | `T1190` | `metadata.http_path` (containing traversal sequence) | `session_id`, `source_ip` | Missing traversal pattern |

---

## 3. Evidence Extraction & Sanitization Pipeline

During evaluation, `MappingEvaluator` processes telemetry through the sanitization filter:
1. Strips sensitive keys: `password`, `auth_token`, `private_key`, `secret`, `credential`.
2. Extracts telemetry identifiers: `event_id`, `event_category`, `event_type`, `outcome`, `source_ip`, `session_id`.
3. Creates persistent association in `attack_mapping_evidence` table with role `TRIGGERING_TELEMETRY` (relevance 100) or `CORROBORATING_EVENT` (relevance 80).
4. Links evidence to the parent alert and detection result for end-to-end auditability.
